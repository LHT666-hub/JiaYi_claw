# 家医 Claw 居民小程序设计系统

更新日期：2026-08-11

## 端侧定位

- 微信小程序是居民与家属的主产品，覆盖 Claw、服务、消息和账户。
- Web 是医生、家医团队与管理员的工作台；居民 Web 仅作为微信内 H5 兼容与展示入口。
- 两端共用服务状态机、权限、Skill Registry 和审计，但不强求相同布局。

## 体验原则

1. **摘要先于功能清单**：首页先显示当前服务对象、正在办理、近期坐班和未读消息，再提供入口。
2. **Claw 是服务入口**：AI 的价值是把一句话变成可核对的服务动作，而不是把用户困在聊天页。
3. **信息与动作分层**：已审核信息可直接查看；预约、转诊、续方和健康事实必须再次确认。
4. **一屏一个主任务**：服务页使用“办服务 / 看排班 / 看资讯”分段，避免所有板块同屏竞争。
5. **隐私可见可控**：默认不保存对话原文，只保存 30 天结构化服务轨迹，并提供清除入口。
6. **来源和状态可信**：排班、活动和文章显示核验状态；外部页面必须经后端白名单解析。

## 视觉层级

- 页面底色：中性浅灰绿，避免整屏奶油色导致内容层级消失。
- 主要内容面：白色或低饱和语义色；普通列表使用一个分组面和行分隔，不给每一行单独套卡片。
- 品牌主色：深海军蓝，用于 Claw 主入口、提交按钮和高权重标题。
- 健康协同色：低饱和绿色，用于已绑定、已核验和家医服务状态。
- 辅助语义色：蓝色表示排班，琥珀表示转诊路径，莓红表示药事，砖红只表示风险。
- 圆角分为 19、28、30、38 四档；胶囊只用于状态、分段选择和单一动作。
- 阴影只用于 Claw 主入口、浮动输入区和一级分组面，不给文字、图标或普通行添加立体效果。

## 动效与反馈

- 按压反馈：160ms，缩放不低于 `0.975`，不使用夸张弹跳。
- 新消息与回复：260ms 的轻微上移和淡入，表达“内容已到达”。
- 录音：仅录音状态使用低频脉冲，并始终同时显示文字状态。
- 列表和分段切换不使用装饰性横飞或大幅缩放。
- 尊重系统减少动态效果设置；动效永远不是状态的唯一表达方式。

## 核心页面结构

- 首页：身份与社区 -> Claw 主操作 -> 今日摘要 -> 紧急提示。
- 服务：家医网络 -> 办服务/排班/资讯分段 -> 对应的单一内容面。
- 消息：渠道状态 -> 收件箱；支持逐条和全部已读。
- 我的：认证身份 -> 家医绑定 -> 数据摘要 -> 授权与安全设置。
- Claw：服务对象 -> 可清除轨迹 -> 安全提示 -> 多轮问答 -> 语音/文字输入。

## 参考来源与边界

- Apple Human Interface Guidelines：借鉴层级、和谐、平台一致性、目的明确的动效和减少动态效果；小程序不是 iOS 原生应用，不复制 Liquid Glass 或系统控件外观。
- Apple Health：借鉴“摘要、趋势、共享、隐私控制”信息结构；首版没有正式 HealthKit 数据，不伪造趋势。
- Epic Emmie：借鉴对话内预约/改期、基于用户资料回答、人工接管和主动提醒；不复制 Epic/FHIR 机构流程。
- NHS App：借鉴消息收件箱、预约提醒和多渠道兜底；国内渠道与身份体系按本地规则实现。
- `vermont42/iOS-Design-Agent-Skill`（MIT）：借鉴字体、颜色、空间、动效和景深五维审查方法；未复制 SwiftUI 代码，也不作为运行时依赖。

## 验收

- 375、390、430 宽度下无横向滚动、文字遮挡或底栏覆盖。
- 重要按钮触控高度不低于 44 CSS px 对应尺寸。
- 颜色之外必须有文字或形状表达状态。
- 动效关闭后所有任务仍可完成。
- 空、加载、失败、未授权、信息过期和人工处理中都有明确状态。
