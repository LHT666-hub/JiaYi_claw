# 官方知识库维护规范

家医 Claw 将“通用大模型能力”“可信知识”“实时业务事实”分层处理，避免把所有问题都塞进 RAG，也避免用静态知识库回答本应实时核验的信息。

## 1. 三类数据分别放哪里

### A. 政策、指南、稳定服务规则 → `public_info_entries` + RAG

适合：

- 国家、上海市、奉贤区家庭医生和基层慢病政策；
- 家庭医生签约、长处方、慢病管理、老年人体检等公开规则；
- 社区卫生服务中心稳定的地址、电话、服务能力；
- 经官方来源核验的周期性门诊安排。

Git 中的 `data/official-public-info.json` 是一份版本化、可审计的官方知识种子。生产数据库可以通过 `npm run sync:official-knowledge` 同步，发布后由现有数据库触发器进入 RAG 索引队列。

### B. 活动、通知、阶段性公告 → `content_items`

活动具有明确时效，应保留发布时间、有效期和原始链接。活动结束后可以作为历史事实留存，但不能继续被回答成“当前活动”。

### C. 医生个人排班、今日号源、药品库存 → 结构化业务表

- 医生排班：`practitioner_schedules`
- 预约/任务进度：`service_requests`
- 药品库存：应接机构实时系统或专门结构化表

这类信息更新频率高，不能仅依赖 RAG。若没有当前结构化来源，Claw 必须明确提示“无法核验当前安排”，不得根据历史公告推断“今天谁坐班”。

## 2. 来源优先级

1. 国家卫生健康委员会等国家主管部门；
2. 上海市人民政府、上海市卫生健康委员会；
3. 奉贤区人民政府、奉贤区卫生健康委员会；
4. 社区卫生服务中心官方页面/官方公众号；
5. 其他来源仅作线索，不直接作为居民端当前事实。

来源发生冲突时，以同一事项中**发布日期更近、主管层级更直接、信息更具体**的官方来源为优先，并在知识条目中记录冲突说明。

## 3. 当前重点覆盖（核验日期：2026-09-06）

- 国家：家庭医生基本服务包、2025—2027签约服务感受度措施、基层慢病全流程健康管理、慢病能力建设、2026—2028基层医疗质量改善、高血压基层管理标准。
- 上海：家庭医生签约服务规范（2024版）、2026基层卫生工作要点、2026老龄健康和慢病防治工作要点、“互联网+”家庭医生签约服务。
- 奉贤：2026老年人免费健康体检政策与便民安排、家庭医生签约服务能力提升。
- 南桥：中心地址、接种门诊安排、慢病支持/体检解读/中医/筛查/康复能力、尚贤服务站中医特色门诊。
- 海湾：新址与电话、中心及五四/海旅分中心接种安排、社区医院能力、中心/分中心/服务站服务网络。

## 4. 时效规则

- 当前门诊时间、接种安排：建议 30—90 天重新核验；当前知识条目设置短有效期，过期自动视为 stale。
- 活动：有效期不超过活动结束时间；已结束活动不得作为当前活动推荐。
- 地址/电话/机构服务能力：建议至少每 6 个月核验一次，遇迁址或机构整合立即更新。
- 年度政策/年度工作要点：至少每年更新一次；有新版本时旧版本标记为历史。
- 国家/上海长期规范：发现修订、废止或替代文件后立即更新。

## 5. 同步到 Supabase / RAG

生产环境准备：

- `NEXT_PUBLIC_SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- 可选：`NEXT_PUBLIC_APP_URL`（或 `APP_URL`）+ `CRON_SECRET`，用于同步后立即处理 RAG 索引队列。

先检查：

```bash
npm run sync:official-knowledge:dry
```

写入生产库并触发索引：

```bash
npm run sync:official-knowledge
```

脚本以稳定 UUID 对知识条目进行 upsert，不会把真实密钥写入 Git。

## 6. 质量边界

- 不把“某医生本周/今天坐诊”写成长期知识，除非存在当期官方排班且设置短有效期。
- 不把过往活动包装成正在进行的活动。
- 不因“网上能搜到”就视为可信，居民端事实优先官方来源。
- RAG 只增强可信事实；基础医学概念仍由基础大模型回答。
- 涉及个人诊断、处方调整、急症风险时，继续先走安全规则和医生兜底。
